# Migration checklist

Generated by `python3 scripts/repo_inventory.py <repos-dir> --output docs/migration-checklist.md` from the
GitHub workflows of the local clones and, with a GitHub token, the owner's repository list. Regenerating keeps
the *Prepared branch* and *Moved* columns, and the sections after the table. Nothing here is written by hand
except those.

**Run the tool with Windows Python and git** (`python scripts/repo_inventory.py D:/Repositories --output
docs/migration-checklist.md` from Windows). In WSL, git sees the clones' CRLF line endings as changes and shows
nearly every clone dirty; Windows git does not.

- **Kind** is the spec's table ("Every repository"; `site (Vercel)` marks the five Vercel projects). Where what the
  clone or GitHub shows differs, *Notes* says so; the Kind stays the spec's.
- **Jobs** are `<workflow>/<job> on <runs-on> <verdict>`: `→ check <job>` (a job on `ubuntu-*`: it leaves
  `.github/workflows` and becomes a check), `→ release (release.build)` (a job on `ubuntu-*` in a `release*.yml`
  workflow) and `→ publish (publish.nuget)` (in a `publish-package*.yml` workflow), which plan 3 runs on the
  release agent rather than as checks, `stays (Actions)` (`windows-*` and `macos-*`),
  `goes (Pages)`, `goes (Vercel)` or `goes (branch-policy)` (the workflow is deleted), or `unknown — check by
  hand` (a runner that is an expression this cannot resolve). A `${{ matrix.os }}` is expanded into one line per
  operating system. `dependabot.yml` goes too; Renovate replaces it.
- **Branch model** is `release` where a `branch-policy.yml` workflow exists today, else `basic`.
- **Clone** is the state of `D:\Repositories\<repo>` when this was generated: `clean`, `dirty` (the move skips
  it) or `missing` (cloned from GitHub first, read-only).
- **Prepared branch** is filled when a repository's `feature/move-to-forgejo` branch is ready (never pushed);
  **Moved** is filled by the owner after the cutover.

## Check names

Written by hand, and kept when the table is regenerated. What each workflow job of the table became: every
`→ check` and `stays (Actions)` job is here, and the jobs whose results a check now makes. Tasks 8–13 write
these names into each repository's `yggdrasil.yml`, and `catalog.yaml` lists them in the entry's `checks`
(each job runs only its own entry's checks, all of them required on Forgejo) or `actionsChecks` (the Windows
and macOS jobs, by the name GitHub reports). `scripts/test_catalog.py` checks the three agree.

- `check <name>`: a check of the catalog entry (or entries) of that repository. A job's name is kept where it
  makes a check name (lowercase letters, digits, `.`, `_`, `-`); otherwise a short one says what it runs.
- `actionsCheck <name>`: stays on GitHub Actions, required on `develop` under that name.
- `release.build` / `release.windows`: the release files (`release` in `yggdrasil.yml`), not a check.
- `not required` / `dropped`: no catalog check, with the reason (`not required` jobs stay on GitHub Actions).

## Notes for the repository tasks

Written by hand, and kept when the table is regenerated: what a repository's branch must do because of a catalog
decision above.

- **dotnet-data** (Task 9): its tags stay `<package>@<version>` (`tags: "*@[0-9]*"` in the catalog). The pipeline sets
  `RELEASE_TAG` to the whole tag and `RELEASE_VERSION` to what follows its last `@`, so its `ci/pack.sh` must read
  `RELEASE_TAG` and pack only that package, not every package of the solution at that version.
- **yggdrasil** (Task 8): `ci.yml/pipeline-live` stays a GitHub Actions workflow (manual, on the GitHub copy).
  `yggdrasil.yml` must not define a `pipeline-live` check: no catalog entry names it, so describe would warn that
  it never runs and mark every build unstable.
- **alexandria-api** (Task 10): `ci.yml/performance` stays a GitHub Actions workflow (pushes only, non-gating), not
  a check: keep its workflow when trimming `.github/workflows`.
- **cerberus-ui** (Task 11): released by the owner's `v*` tags like alexandria-ui. Its `build.yml` Linux jobs
  (gate, web, android, linux) become `release.build` in `yggdrasil.yml`, and its Windows job the release's
  `release.windows` workflow.
- **heimdall-api** (Task 8): the docs site's image is `docs.Dockerfile` (`stacks/heimdall-api-docs.yml`), since the
  repository's `Dockerfile` is the API's.
